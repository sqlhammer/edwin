Creating Skills

What you'll need

  • EDWIN installed and configured
  • A task you do more than once
  • 5–10 minutes to teach EDWIN how you do it

How long this takes

10–15 minutes for your first skill. Faster once you're familiar with the process.

What is skill creation?

EDWIN can learn your workflows and turn them into skills — no coding required. When you do something twice, EDWIN notices and offers to capture it. You confirm what it saw, fill in any gaps, and EDWIN writes the skill for you.

This is one of EDWIN's most powerful features: it means you're not stuck with the 23 built-in skills. You can teach EDWIN anything you do repeatedly.

The journey: creating a skill from start to finish

The best way to understand skill creation is to watch it happen. Here's Alex, who backs up a database every week and wants to turn that into a skill.

Act One: EDWIN notices

Alex has just finished backing up the database — for the second time this session. EDWIN's workflow observation system fires.

EDWIN: You've done that twice now. Want me to learn it as a skill?

Alex: Yeah, I do this every week.

EDWIN switches into observation mode. It already watched Alex perform the task twice, so most of the workflow is visible in the conversation history.

Act Two: confirming what EDWIN saw

EDWIN: I saw you do this twice: export the database, compress it, and upload to S3. Is that the pattern?

Alex: Exactly.

EDWIN confirmed the core steps. Now it asks about the gaps — things observation didn't reveal:

EDWIN: A few questions:

1. What should I call this?

2. Any other times you'd say it, besides "run the backup"?

3. Do you always compress, or only when the dump is large?

Alex: Call it "weekly-backup". I'd also say "back up the database" or "run the S3 backup". Always compress it.

EDWIN has everything it needs. It plays the workflow back to confirm:

EDWIN: So: you back up the database weekly, triggered by "run the backup" or "back up the database", starting with the DB credentials and S3 bucket name, then export → compress → upload. Right?

Alex: Yep.

Act Three: the workflow breakdown

EDWIN writes a workflow breakdown file — a structured document that captures what Alex does. It's saved to the EDWIN folder at user/workflows/weekly-backup.md.

EDWIN: Workflow documented. When you're ready, I can turn this into a skill — just say "create a skill from my weekly-backup workflow".

What just happened: EDWIN didn't create a skill yet. It created a workflow breakdown — a description of what Alex does. This two-step process (observe → breakdown, then breakdown → skill) means Alex can review and refine the workflow before it becomes a skill.

Act Four: turning the breakdown into a skill

Alex is ready to generate the skill:

Alex: Create a skill from my weekly-backup workflow

EDWIN reads the breakdown and generates a skill using its internal template. It doesn't show Alex the raw code — it summarizes in plain language:

EDWIN: Here's the skill:

What it does: Backs up your database to S3 weekly

When it triggers: "run the backup", "back up the database", "run the S3 backup"

The steps it follows: Asks for DB credentials and S3 bucket, exports the database, compresses the file, uploads to S3, confirms success

Sample run:

You: Run the backup

EDWIN: DB credentials? S3 bucket?

You: (provides details)

EDWIN: Exported. Compressing... Uploaded to s3://your-bucket/backup-2026-08-26.sql.gz. Backup complete.

Look right, or anything to change?

Alex reviews it:

Alex: Looks good.

Act Five: installation

EDWIN validates the skill (checks that all required sections are present, the description is the right length, etc.), then installs it:

EDWIN: Ready to install. This will create core/skills/weekly-backup/ and sync it to your harnesses.

Alex: Do it.

EDWIN creates the skill file, runs the sync engine (the tool that installs skills into Claude), and confirms:

EDWIN: Skill installed: weekly-backup. It's live now — try saying "run the backup".

Alex tries it:

Alex: Run the backup

EDWIN: DB credentials? S3 bucket?

It works. Alex now has a custom skill that remembers the weekly backup workflow.

The two paths to skill creation

There are two ways to create a skill:

Path 1: Observation mode (what we just saw)

  1. Do a task twice in the same conversation
  2. EDWIN offers to learn it
  3. Confirm what EDWIN saw, answer a few questions
  4. EDWIN writes a workflow breakdown
  5. Say "create a skill from my [name] workflow"
  6. Review and install

This is the best path when EDWIN can watch you work.

Path 2: Interview mode

If you haven't done the task yet, or if EDWIN didn't notice, you can teach it directly:

You: Learn how I write my monthly report

EDWIN will ask you a series of questions (batched, not one-at-a-time) about what the workflow accomplishes, when you use it, what steps you follow, and what the result looks like. Then it writes a breakdown, and you proceed to skill creation the same way as observation mode.

What happens behind the scenes

When you create a skill, EDWIN:

  1. Writes a skill file to core/skills/[your-skill-name]/SKILL.md in the EDWIN folder
  2. Runs the sync engine (a tool that copies skills into the right places so Claude can see them)
  3. The skill becomes available immediately — no restart required

Your skill is stored in the core/skills/ directory alongside EDWIN's built-in skills. It's yours to edit, share, or delete.

Creating personas (advanced)

Skills aren't just for tasks — you can also create persona-mode skills that change how EDWIN behaves. For example, the built-in writing-editor persona makes EDWIN act like a patient writing coach.

To create a persona:

You: Create a persona for me

EDWIN: What role should this persona take?

Describe the role (e.g., "a Socratic philosophy teacher", "a stern fitness coach", "a supportive therapist") and answer a few questions about how it should behave. EDWIN will generate a persona-mode skill that you can activate by name:

You: Activate my philosophy teacher

Philosophy Teacher: (EDWIN adopts that persona for the conversation)

Tips for good skills

  • Start with a real workflow. Don't invent a skill you might use someday — capture something you've actually done at least twice.
  • Be specific about triggers. When EDWIN asks "what would you say when you need this?", give the exact phrases you'd use.
  • Name it clearly. Use a name that makes sense to you six months from now. "weekly-backup" is better than "db-thing".
  • Test it right away. Once installed, try the skill immediately to make sure it behaves as expected.
  • Update it when your workflow changes. Say "update my [skill-name] workflow" and EDWIN will ask what changed.

Managing your skills

Your custom skills live in the EDWIN folder at core/skills/. Each skill is a folder with a SKILL.md file inside.

To see all your skills (built-in and custom):

You: List skills

To update a skill:

You: Update my weekly-backup skill

To delete a skill, remove its folder from core/skills/ and run the sync command:

  • Command Prompt or Terminal: npm run sync (from the EDWIN folder)

If something goes wrong

Common issues:

  • EDWIN doesn't offer to learn my workflow: Make sure you've done the task at least twice in the same conversation. If the workflow-observation preference is turned off, EDWIN stays silent. Check your settings: "show my config".
  • Skill doesn't appear after installation: Restart Claude (quit and reopen). Skills should appear immediately, but a restart can help if something is cached.
  • Skill triggers the wrong behavior: The trigger phrases might overlap with another skill. Try being more specific, or update the skill to use more distinctive phrases.
  • I want to edit the skill directly: Advanced users can edit core/skills/[skill-name]/SKILL.md by hand, then run npm run sync. See the EDWIN conventions document for the format.

For more help, see the Troubleshooting guide.
