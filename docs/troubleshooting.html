Troubleshooting

This guide covers common issues when installing, updating, or using EDWIN. Each section starts with the symptom as you experience it, then walks through the fix.

What you'll need

  • Whatever error message or unexpected behaviour you saw — the exact wording helps you find the right section below
  • Terminal (macOS) or Command Prompt (Windows) for some fixes — each step says when
  • Nothing else. You do not need to reinstall EDWIN to work through this guide.

How long this takes

Find your symptom below and read only that section — most fixes take 2 to 5 minutes. You do not need to read this page top to bottom.

Installation Issues

Symptom: "Node.js is not installed and installation was declined" (or the same for Git)

What happened: The installer offered to install the missing tool and did not get a yes. Either you answered no, or nothing was there to answer — this is what you see when the installer runs unattended, from a script, or with its input redirected.

Fix — let it install: Run the installer again and answer Y when it asks. To skip the question entirely:

  1. macOS: open Terminal and run bash ~/Downloads/EDWIN-Install.command --yes
  2. Windows: open Command Prompt and run %USERPROFILE%\Downloads\EDWIN-Install.cmd --yes

Fix — install it yourself instead: One command, no browser needed:

  1. macOS with Homebrew: brew install node git
  2. macOS without Homebrew: xcode-select --install for Git; for Node.js let the EDWIN installer do it, since it verifies the download's checksum for you
  3. Windows: winget install --exact --id OpenJS.NodeJS.LTS --source winget and winget install --exact --id Git.Git --source winget

Then close and reopen your terminal or Command Prompt and run the EDWIN installer again.

Symptom: "Node.js still isn't usable after the install attempt" (or the same for Git)

What happened: The tool was installed, but this window doesn't know about it yet. A terminal is given the list of installed programs when it starts and doesn't notice later additions. Common on Windows.

Fix: Close the window and run the installer again. A fresh window sees the new tool. If it happens a second time, the install genuinely failed — check the log the installer names on screen (install.log in your EDWIN folder) for what the tool's own installer reported.

Symptom (macOS): the installer asks for your password

What happened: Installing Node.js or Git for every user on the machine requires administrator rights, so macOS asks. Nothing has gone wrong.

What to know: The password goes to macOS, not to EDWIN — the installer never sees it and never stores it. If you would rather not be asked, install the tools yourself first with brew install node git, then run the EDWIN installer; it will find them and skip straight past.

Symptom (Windows): "Do you want to allow this app to make changes to your device?"

What happened: Same thing — installing Node.js or Git needs administrator rights, so Windows asks. Click Yes.

If you click No, the installer reports that the tool is still unavailable and stops. Nothing is left half-installed.

Symptom (Windows): "winget is unavailable"

What happened: The installer prefers winget, the software installer built into Windows 10 and 11. Some older or locked-down Windows installations don't have it.

What happens next: Nothing you need to do — the installer falls back to downloading Node.js and Git straight from their official sites and installing them silently. It's a message, not an error. If that fallback also fails, the log will say why.

Symptom (macOS): "Cannot be opened because it is from an unidentified developer"

What happened: macOS blocks the installer because it's not code-signed by a registered Apple developer. This is called "quarantine."

Fix:

  1. Don't double-click the installer again
  2. Right-click (or Control-click) the EDWIN-Install.command file
  3. Choose Open from the menu
  4. A dialog appears asking if you're sure
  5. Click Open
  6. The installer runs

You only need to do this once. After the first run, double-clicking works normally.

Symptom: Skills don't appear after installation

What happened: Claude hasn't reloaded the updated configuration yet.

Fix:

  1. Close Claude Code or Claude Desktop completely
  2. Reopen Claude
  3. Start a new conversation
  4. Try: "List my skills"

If skills still don't appear after restarting:

  1. Check that the file ~/.claude/CLAUDE.md (macOS) or %USERPROFILE%\.claude\CLAUDE.md (Windows) exists
  2. Open it in a text editor
  3. Look for the line # EDWIN near the top
  4. If it's not there, the sync failed — check the log at ~/edwin/install.log or %USERPROFILE%\edwin\install.log

Symptom: "EDWIN doesn't seem to know who I am"

What happened: The onboarding conversation (where EDWIN asks your name and preferences) never ran, or the configuration file is missing.

Fix:

  1. Check if ~/edwin/user/config.json (macOS) or %USERPROFILE%\edwin\user\config.json (Windows) exists
  2. If it doesn't exist, start a conversation with EDWIN
  3. EDWIN will automatically trigger onboarding and ask for your name, preferences, and context setup
  4. Answer the questions
  5. When onboarding finishes, the configuration is saved

If the file exists but EDWIN still doesn't recognize you, the file may be corrupted:

  1. Open the file in a text editor
  2. Check that it looks like valid JSON (starts with {, ends with })
  3. If it's empty or malformed, delete it and trigger onboarding again

Update Issues

Symptom: Update fails with "uncommitted changes detected"

What happened: You've edited files outside the user/ directory, and the updater won't overwrite them.

Fix (if you want to keep your changes):

  1. Open Terminal (macOS) or Command Prompt (Windows)
  2. Navigate to your EDWIN directory: cd ~/edwin (macOS) or cd %USERPROFILE%\edwin (Windows)
  3. Run: git status to see which files changed
  4. Run: git add . to stage your changes
  5. Run: git commit -m "My custom changes" to commit them
  6. Run the updater again

Fix (if you don't need your changes):

  1. Open Terminal (macOS) or Command Prompt (Windows)
  2. Navigate to your EDWIN directory: cd ~/edwin (macOS) or cd %USERPROFILE%\edwin (Windows)
  3. Run: git restore . to discard changes
  4. Run the updater again

Note: Changes in the user/ directory never block updates and are always preserved.

Symptom: Update fails with "failed to pull updates"

What happened: The updater couldn't download from the repository. This happens if you're offline, or if your local branch has diverged from the remote.

Fix (if offline):

  1. Connect to the internet
  2. Run the updater again

Fix (if branch has diverged):

  1. Open Terminal (macOS) or Command Prompt (Windows)
  2. Navigate to your EDWIN directory: cd ~/edwin (macOS) or cd %USERPROFILE%\edwin (Windows)
  3. Run: git status to check the state
  4. Run: git log to see recent commits
  5. If you've made commits you want to keep, push them to a fork or new branch first
  6. If you want to discard local commits and sync with the upstream version, run: git reset --hard origin/main
  7. Run the updater again

Warning: git reset --hard is destructive — it discards all local commits and changes. Only use it if you're certain you don't need them.

Symptom: Update completes but skills don't change

What happened: Claude hasn't reloaded the configuration yet.

Fix:

  1. Close Claude Code or Claude Desktop completely
  2. Reopen Claude
  3. Start a new conversation
  4. Try: "List my skills" to confirm the update

Symptom: Sync engine failed during update

What happened: The update downloaded successfully, but the sync engine (which installs the changes into Claude) encountered an error.

Fix:

  1. Check the log file:
    • macOS: ~/edwin/install.log
    • Windows: %USERPROFILE%\edwin\install.log
  2. Look for the last error message
  3. Common causes:
    • Invalid skill syntax: A skill has malformed frontmatter. This is a bug — report it.
    • File permissions: The sync engine can't write to ~/.claude/. Check that the directory exists and is writable.
    • Disk full: Check available disk space.
  4. If you can't resolve the error, try running the sync engine manually:
    • Open Terminal (macOS) or Command Prompt (Windows)
    • Navigate to EDWIN: cd ~/edwin (macOS) or cd %USERPROFILE%\edwin (Windows)
    • Run: node tools/sync/engine.mjs --target all
    • Watch for errors and note the exact message

Scheduled Task Issues

Symptom: Scheduled task never fires

What happened: The task is registered, but the OS isn't running it. Common causes: machine was asleep, the OS job is missing, or the job file is malformed.

Fix:

  1. Ask EDWIN: "List my scheduled tasks"
  2. If EDWIN reports a mismatch ("task is in the registry but the OS job is missing"), choose to recreate it
  3. If no mismatch is reported, check manually:

macOS:

  1. Open Terminal
  2. Run: launchctl list | grep edwin
  3. You should see one or more lines starting with com.edwin.task
  4. If nothing appears, the job isn't loaded
  5. Check that the plist file exists: ls ~/Library/LaunchAgents/com.edwin.task.*
  6. If it exists, load it: launchctl load ~/Library/LaunchAgents/com.edwin.task.[id].plist

Windows:

  1. Open Command Prompt
  2. Run: schtasks /Query /TN "EDWIN\*"
  3. You should see your scheduled tasks listed
  4. If nothing appears, the job is missing — ask EDWIN to recreate it

Machine must be awake: Scheduled tasks only run when your computer is powered on and awake. If the machine is asleep at the scheduled time, the task won't run.

Symptom: Scheduled task runs but produces no output

What happened: The task fired, but the prompt didn't generate the expected result, or the log file isn't being written.

Fix:

  1. Check the log file:
    • macOS: ~/edwin/user/schedule-logs/[task-id].log
    • Windows: %USERPROFILE%\edwin\user\schedule-logs\[task-id].log
  2. If the log file is empty or missing, the task didn't run — see "Scheduled task never fires" above
  3. If the log file exists but the output is wrong, refine the prompt and reschedule

Web Portal Issues

Symptom: Portal rejects pasted bundle as too long

What happened: The bundle exceeds the portal's character limit for custom instructions.

Fix:

  1. Check the output folder for a file named CONDENSED_VARIANT.md or FAILURE_MANIFEST.md
  2. If a condensed variant exists, paste that instead — it omits full skill bodies to fit the limit
  3. If even the condensed variant is too long:
    • Export a narrower context (Work or Home instead of Global)
    • Regenerate without personal data (remove --include-memory and --include-brags)
    • Use a different portal with a larger or unknown limit (Claude Projects or Gemini instead of Copilot)

Symptom: EDWIN in a web portal doesn't remember things between sessions

What happened: Web portal bundles are static snapshots. EDWIN can't update its own instructions in a portal.

Fix:

This is a limitation of web portals, not a bug. To keep EDWIN's memory current:

  1. Use EDWIN locally (in Claude Code or Claude Desktop) for memory-related tasks
  2. Regenerate and re-paste bundles periodically if you need an updated snapshot
  3. Or, accept that the portal version has static memory from when you generated the bundle

General Issues

Symptom: EDWIN doesn't recognize a skill trigger

What happened: Your request didn't match any skill's trigger phrases closely enough.

Fix:

  1. Try being more explicit: "Use the briefing skill on this article"
  2. Ask EDWIN: "List my skills" to see what's available
  3. Check that the skill you want is in your active context (or switch to Global to see all skills)

Symptom: EDWIN's responses are too brief or too verbose

What happened: The verbosity preference doesn't match what you want.

Fix:

You: I'd like more detailed responses

EDWIN: (Adjusts verbosity to "detailed")

You: Go back to concise responses

EDWIN: (Adjusts verbosity to "concise")

Still stuck?

If your issue isn't covered here:

  1. Check the EDWIN repository for known issues and updates
  2. Ask EDWIN directly: "How do I [your problem]?" — EDWIN knows how EDWIN works
  3. File an issue on GitHub with:
    • The symptom you're seeing
    • What you expected to happen
    • Steps to reproduce
    • Your OS and EDWIN version (check ~/edwin/core/VERSION)
