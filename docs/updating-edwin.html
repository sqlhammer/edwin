Updating EDWIN

Updating EDWIN pulls the latest skills and framework improvements from the repository while preserving all your personal data — memory, accomplishments, custom workflows, configuration, and scheduled tasks.

What you'll need

  • EDWIN installed (see Getting Started)
  • An internet connection

How long this takes

1–2 minutes. The update runs automatically once you start it.

What gets updated

An update pulls the latest version of:

  • Skills — new skills, improvements to existing ones
  • Persona — refinements to how EDWIN works
  • Tools and scripts — installers, schedulers, validators, bundle generators
  • Documentation — these guides

What gets preserved

Your personal data is stored in the user/ directory, which is explicitly excluded from version control. An update never touches:

Location What's there
user/config.json Your name, preferences, contexts, paths
user/state.json Active context, session state
user/memory/ Everything EDWIN remembers about you
user/brags/ Your logged accomplishments
user/workflows/ Custom skills you've created
user/schedule.json Scheduled tasks registry
user/schedule-prompts/ Prompts for scheduled tasks
user/schedule-logs/ Output from scheduled runs

Guarantee: The user/ directory is listed in .gitignore and is never synced, committed, or overwritten by an update. Your data stays on your machine and survives every update.

Custom edits to CLAUDE.md

If you've edited your ~/.claude/CLAUDE.md file directly, those edits are preserved as long as they're outside the managed markers:

<!-- EDWIN:BEGIN -->
...(EDWIN-managed content)...
<!-- EDWIN:END -->

Anything you write before the BEGIN marker or after the END marker is never touched by the sync engine. Content between the markers is regenerated from core/ on every sync.

Running the update

macOS

Step 1: Find the update script

Open Finder and navigate to:

~/edwin/tools/installers/

You'll see a file named EDWIN-Update.command.

Step 2: Run the updater

Double-click EDWIN-Update.command.

A Terminal window opens and the updater runs automatically.

Step 3: Wait for completion

The updater will:

  1. Check that EDWIN is installed
  2. Check for uncommitted changes (excluding the user/ directory)
  3. Download updates from the repository
  4. Run the sync engine to update your Claude installation

When you see "Update Complete!", the update is done.

Step 4: Restart Claude

Close and reopen Claude Code or Claude Desktop to load the changes.

Windows

Step 1: Find the update script

Open File Explorer and navigate to:

%USERPROFILE%\edwin\tools\installers\

You'll see a file named EDWIN-Update.cmd.

Step 2: Run the updater

Double-click EDWIN-Update.cmd.

A Command Prompt window opens and the updater runs automatically.

Step 3: Wait for completion

The updater will:

  1. Check that EDWIN is installed
  2. Check for uncommitted changes (excluding the user\ directory)
  3. Download updates from the repository
  4. Run the sync engine to update your Claude installation

When you see "Update Complete!", the update is done.

Step 4: Restart Claude

Close and reopen Claude Code or Claude Desktop to load the changes.

If the update fails

The updater checks for conditions that would prevent a clean update and stops if it finds any:

Uncommitted changes detected

If you've edited files outside the user/ directory (like skills in core/skills/), the updater won't overwrite them. To proceed:

  1. Commit your changes: If you've made intentional edits, commit them with Git before updating.
  2. Stash your changes: Run git stash in the EDWIN directory to save your changes temporarily, then run the update, then git stash pop to restore them.
  3. Discard your changes: If the edits were experiments and you don't need them, run git restore . to discard them, then update.

Note: Changes in the user/ directory are always preserved and do not block updates.

Not connected to the internet

The updater needs an internet connection to download updates. Connect to the internet and try again.

Branch has diverged

If your local branch has commits that aren't in the remote repository, the update will fail. This typically happens if you've committed custom changes. To resolve:

  1. Run git status in the EDWIN directory to see the state
  2. Run git log to see your commits
  3. If you want to keep your changes, push them to a fork or a new branch
  4. If you want to discard them, run git reset --hard origin/main (this is destructive — only do it if you're certain)

Sync engine failed

If the sync engine encounters an error after downloading updates, check the log file:

  • macOS: ~/edwin/install.log
  • Windows: %USERPROFILE%\edwin\install.log

Common causes:

  • Invalid skill syntax: A new skill has a malformed frontmatter block. Report this as a bug.
  • File permissions: The sync engine can't write to ~/.claude/ or ~/.claude-desktop/. Check that the directories exist and are writable.

For help, see the Troubleshooting guide.

Updating web portal bundles

After updating EDWIN locally, your web portal bundles (for claude.ai, Gemini, Copilot) become stale. To regenerate them:

  1. Open Terminal (macOS) or Command Prompt (Windows)
  2. Navigate to your EDWIN directory: cd ~/edwin (macOS) or cd %USERPROFILE%\edwin (Windows)
  3. Run: node tools/bundle/build-bundle.mjs --context [YourContext] --portal all --diff
  4. The script regenerates only changed bundles and prints re-paste instructions

See Using EDWIN in Web Portals for details.

How often to update

There's no automatic update mechanism. You control when to update. Consider updating when:

  • A new version is announced with features you want
  • A bug you've encountered is fixed
  • You're troubleshooting an issue and want to rule out an outdated installation

Check the EDWIN repository for release notes and announcements.

Next steps

  • After updating, restart Claude to load the changes
  • Regenerate web portal bundles if you use them
  • If something goes wrong, see the Troubleshooting guide
