All 38 checks run in a temp root with a temp `HOME`. The suite hashes the real `user/` directory before and
after the run and fails if the hash changes, so a test that reaches into live personal data is itself a
test failure rather than a silent side effect.

| Installers | macOS `.command` LF endings, no-tty without a repo URL fails with `--repo-url` guidance, Windows `.cmd` LF-normalised in the repo with `eol=crlf` on checkout, `.command` `eol=lf` on checkout | 4/4 |
| Personal data | full-repo `git grep` audit against the denylist patterns | 1/1 |
| Pruning / safety | removed skills pruned on re-sync, real `user/` unchanged | 2/2 |

Three assertions worth naming, because each one guards a bug that was actually shipped and caught:

- **`claude --plugin-dir` actually lists them.** `claude plugin validate` passes on a plugin whose skills do
  not resolve. Only loading the plugin proves discovery works.
- **Over-limit portal fails loudly.** Not "the bundle is within limits" — the opposite assertion. It drives
  the real limit path via `--limits` with a shrunken threshold and asserts the tool exits non-zero *and*
  prints no success marker. An earlier version of this test passed because an invented portal name failed
  argument validation before any limit was consulted.
- **`eol` on checkout, not in the working tree.** Line-ending guarantees come from `.gitattributes`, which
  does not retroactively fix files committed before it existed. The test asserts the committed blob is
  LF-normalised *and* that `git check-attr` reports the intended `eol`, because a stale working tree reports
  the wrong answer either way.

## Defects found and fixed

Every one of these was found by re-running the work rather than by reading a completion report. All are
fixed in 0.2.0; all are in the CHANGELOG under **Fixed**.

| # | Defect | Consequence |
|---|---|---|
| 1 | `edwin-doctor` counted a trailing empty line as a line | Every size check off by one; a 250-line skill flagged as over the 250-line guideline. Also affected the persona and memory-digest budgets. |
| 2 | `brags-files-parse` accepted a wrong-shaped `categories.json` | Downstream `brags-categories-valid` then blamed `brags.md` for every entry — pointing the user at the wrong file. |
| 3 | Both macOS `.command` installers aborted silently | `clear` exits non-zero when `TERM` is unset or minimal; as the first statement of `main()` under `set -euo pipefail` it killed the installer with zero output. |
| 4 | `brags.mjs` month labels shifted a month | `new Date('YYYY-MM-01')` parses UTC, renders local — wrong label for anyone behind UTC. Now derived by string parsing. |
| 5 | `run-e2e.mjs` contained a literal `/Users/` path | Made `npm run doctor` exit 1, breaking this work unit's own acceptance criterion. |
| 6 | The personal-data audit found its own pattern literals once committed | The check passed while untracked and failed the moment it was tracked. Patterns are now assembled from fragments. |

Two test-quality defects, recorded because a green suite that asserts the wrong thing is worse than a
missing test:

| # | Defect | Consequence |
|---|---|---|
| 7 | The over-limit bundle test asserted the opposite of its name | It used an invented portal name, so `build-bundle.mjs` failed at argument validation before consulting any limit. The test would have passed identically against the real limits file. Rewritten with an explicit "did we reach the limit check?" guard, and `--limits` added so it drives the real path without mutating the tracked config. |
| 8 | Four checks were marked skipped as "blocked" when they were not | The plist skip cited "not created in dry-run" — dry-run prints the full XML; the caller had used `--prompt` instead of `--prompt-file`. Investigating the installer skip is what surfaced defect 3. All four are now real checks. |

### Accepted, not fixed

- **Instruction limits for Claude Projects and Gemini Gems are unknown.** Neither is published.
  `portal-limits.json` records them as `verified: false` with a null limit, and the exporter reports the
  size and says the limit is unpublished rather than guessing a threshold. Deferred to
  [roadmap-v0.3.md](../roadmap-v0.3.md).
- **`requires:` in skill frontmatter is declarative only.** Nothing refuses to install a skill whose
  requirements the harness cannot meet. Deferred.

## Fictional-user sweep

- `npm run doctor` → clean, including its personal-data scan.
- `git grep -inE 'derik|hammer|sqlhammer|C:\\repos|/Users/[a-z]'` finds nothing outside `specs/` and
  `docs/testing/` except the project's own canonical remote, which conventions §11 permits in install
  instructions. The automated audit enforces this per-line rather than by exempting whole files: a line
  containing the account name is allowed only if it also contains `github.com/<owner>/edwin` or
  `github:<owner>/edwin`. The one non-URL exception is `.claude-plugin/marketplace.json`, whose schema
  requires `owner.name` to be the hosting account.
- `user/` is gitignored apart from its README and contains no committed content.
- `tools/validate/denylist.txt` ships with commented placeholders only, so the file itself stays portable.
  A user adds their own patterns; nothing personal is baked in.
